## 1. 3줄 요약

1. Claude는 Anthropic의 대규모 언어 모델로 **긴 컨텍스트(20만 토큰)·코드 생성/디버깅·이미지 이해·안전성 설계**가 강점이며, **웹(claude.ai)과 API** 두 경로로 쓸 수 있습니다. `(p.2~4)`
2. 이 가이드의 중심축은 **프롬프트 품질**입니다. 기초에서는 **맥락·지시사항·입력데이터·출력형식·제약조건 5요소 구조**를, 중급에서는 **XML 태그·시스템 프롬프트·사고의 연쇄(CoT)·Few-shot** 4대 고급 기법을 다룹니다. `(p.6~11)`
3. 후반부는 실전 적용으로, **Claude Code(터미널 코딩 도구)·데이터 분석·프롬프트 체이닝·tool-use·맞춤형 챗봇·긴 컨텍스트·멀티모달**을 거쳐 **개발 라이프사이클 전체를 자동화하는 워크플로우**까지 코드와 함께 제시합니다. `(p.11~28)`

## 2. 꼭 알아야 할 핵심 내용 5개

### ① 프롬프트 5요소 구조 — 모든 기법의 뼈대 `(p.6~7)`

| # | 요소 | 역할 |
|---|------|------|
| 1 | **맥락 (Context)** | 작업의 배경·목적·필요 정보 |
| 2 | **지시사항 (Instructions)** | 모델이 수행할 작업을 명확히 |
| 3 | **입력 데이터 (Input)** | 실제로 처리할 콘텐츠 |
| 4 | **출력 형식 (Output Format)** | 원하는 응답의 구조와 형식 |
| 5 | **제약 조건 (Constraints)** | 제한사항·경계 설정 |

**"개선 전 → 개선 후" 대비** `(p.7)`

- 개선 전: "이메일 작성해줘"
- 개선 후: "신제품 출시 안내를 위한 고객 이메일을 작성해주세요. **이메일은 간결하게 300자 이내**로, 제품의 **주요 특징 3가지**를 강조하고 **구매 링크**를 포함해야 합니다."
- 개선 전: "자바스크립트 도와줘"
- 개선 후: "사용자가 버튼을 클릭하면 폼 데이터를 검증하고 **AJAX를 사용하여 서버에 제출**하는 자바스크립트 함수를 작성해주세요. **각 단계에 주석**을 포함하고, 유효성 검사에는 **이메일 형식과 필수 필드 확인**이 포함되어야 합니다."

기본 3기법 `(p.7~8)`: **역할 부여** / **형식 지정** / **단계별 안내**
응답 조정 `(p.9)`: 전문성 수준("초보자를 위해 설명해주세요"), 길이("100단어 이내로 요약해주세요"), 톤("친근한 톤으로") + 웹 **Custom Instructions**로 상시 적용

### ② 고급 프롬프트 4대 기법 `(p.9~11)`

| 기법 | 핵심 | 근거 |
|------|------|------|
| **XML 태그 활용** | `<instruction>`, `<customer_feedback>`, `<output_format>` 처럼 태그로 프롬프트 구획을 나눔. "Claude는 XML 태그를 통해 입력의 구조를 인식하고 처리하는 데 매우 능숙합니다." | p.9~10 |
| **시스템 프롬프트** | API의 `system=` 파라미터로 역할·행동 규칙 지정. **전체 대화 세션에 지속 적용**됨 (예: "당신은 경험 많은 보안 전문가입니다…") | p.10 |
| **사고의 연쇄 (CoT)** | "각 단계를 자세히 설명하고, 최종 답을 제시하기 전에 중간 계산 과정을…" — 중간 추론을 보여주게 해 정확도를 높임 | p.10~11 |
| **Few-shot 프롬프팅** | 예시 2~3개를 먼저 주고 "이 형식에 맞춰" 나머지를 처리하게 함 (API·머신러닝 설명 예시 → 블록체인·클라우드 컴퓨팅·DNS·방화벽) | p.11 |

### ③ Claude Code — 터미널 전용 코딩 도구 `(p.11~13)`

> "Claude Code는 Anthropic의 전용 코딩 도구로, 터미널을 통해 직접 사용할 수 있습니다." `(p.11)`

**설치 3단계** `(p.12)`

```bash
# 1. NodeJS 18+ 설치 후 NPM으로 설치
npm install -g @anthropic-ai/claude-code
# 2. 터미널에서 실행
claude
# 3. Anthropic 계정으로 로그인 및 설정 완료
```

**코드 요청 프롬프트 3패턴** `(p.12~13)`

1. **명확한 요구사항 제시** — 함수명 / 목적 / 입력 / 출력 / 요구사항(정규표현식 사용, 중복 제거, 입력값 유효성 검사, 주석 및 docstring)까지 명시
2. **기존 코드 개선 요청** — 개선 사항을 항목으로 지정: 시간 복잡도 개선(현재 O(n²)), 최신 JavaScript 문법 적용, 변수명 명확화, 주석·예외 처리 추가
3. **알고리즘 설명 요청** — 개요 / 시간·공간 복잡도 / 의사 코드 / 구현 예제 / 단계별 과정 / 장단점 순으로 출력 형식 지정

**데이터 분석 활용** `(p.13~14)`: 전처리·통계·머신러닝·시각화 코드 생성, **CSV 파일 업로드 후 직접 분석** 및 자동 리포트 생성 (pandas·matplotlib·seaborn 예시 포함)

### ④ 프롬프트 체이닝과 tool-use `(p.14~19)`

**프롬프트 체이닝** `(p.14~16)` — "각 단계의 출력을 다음 단계의 입력으로 사용하는 기법"

- 기본 구조: **① 작업 분해 → ② 순차적 실행 → ③ 결과 통합**
- 예시(학술 논문): 단계1 연구 질문 도출 → 단계2 문헌 검토 계획 → 단계3 연구 방법론 설계
- 전략 4가지: **중간 결과 검토**(오류 전파 방지), 명확한 지시사항, 맥락 유지, 복잡성 관리

**도구 사용(tool-use)** `(p.16~19)` — "이 기능은 **API를 통해** 제공됩니다"

- 가능한 작업: 웹 검색 / 데이터베이스 쿼리 / API 호출 / 계산 실행 / 파일 처리
- 구현 흐름: `tools=[{"name", "description", "input_schema"}]` 정의 → 응답이 `tool_use` 타입이면 함수 실행 → 결과를 `tool_result`로 되돌려 대화 계속 (날씨 API 예제)
- 설계 고려사항: 도구 설명 명확화 / 입력 스키마 정확 정의 / 오류 처리 / **보안 — 권한은 필요한 최소한으로, 입력값 검증 철저히**

**맞춤형 챗봇** `(p.19~21)`: 웹 **Claude Projects** 5단계(프로젝트 생성 → 작업 정의 → 컨텍스트 제공 → 초기 지침 설정 → 테스트·배포) 또는 **Flask + API** 직접 구현. 업무 자동화 사례 4가지 — 고객 지원, 내부 지식 관리, **코드 리뷰 보조**, 문서 요약·분석

---

### ⑤ 개발 워크플로우 통합과 그 한계 `(p.22~28)`

**긴 컨텍스트 전략** `(p.22~23)`: 20만 토큰으로 전체 논문·계약서·**대규모 코드베이스** 통째 분석. 팁 — 불필요한 텍스트 제거로 토큰 절약, XML `<document_section>`으로 구획, **중요한 섹션은 앞부분에 배치**(앞부분 정보가 더 큰 영향), 초점을 좁힌 질문, 단계적 분석

**멀티모달** `(p.23~25)`: 차트·스크린샷·다이어그램·수식·코드 이미지 분석. 활용 — UI/UX 리뷰, 오류 스크린샷 디버깅, 레거시 코드 현대화, 기술 문서화. 팁 — 고해상도 이미지, 관심 영역 지정, 맥락 동반 제공, 구체적 질문

**개발 라이프사이클 4단계 통합** `(p.25)`: ①요구사항 분석·설계 → ②코딩·개발(코드 스켈레톤 생성) → ③테스트·품질 보증 → ④배포·유지보수. p.25~28에는 `analyze_requirements` → `generate_code_skeleton` → `create_test_cases` → `pytest` 실행 → `run_code_review` → `generate_documentation`으로 이어지는 **전체 파이프라인 Python 코드**가 실려 있습니다.

**고급 통합 전략** `(p.28)`: CI/CD 파이프라인(GitHub Actions·Jenkins), IDE 확장 프로그램(VS Code·IntelliJ), 커스텀 CLI 도구, API 게이트웨이

> 🚨 **문서가 가장 강조하는 경고** `(p.28)`
> - **모든 자동 생성 코드는 인간 개발자의 검토가 필요합니다.**
> - 중요한 비즈니스 로직이나 보안 관련 코드는 특히 주의 깊게 검토
> - 자동화 의존도를 점진적으로 높이고, 충분한 테스트 후 프로덕션에 적용
> - **개인정보나 기밀 정보가 포함된 코드는 Claude에 전송하지 말 것**

## 3. 어려운 용어 풀이

| 용어 | 쉬운 설명 | 근거 |
|------|-----------|------|
| **LLM (대규모 언어 모델)** | 방대한 글을 학습해 다음에 올 말을 예측하는 방식으로 문장을 만드는 AI. | p.2 |
| **토큰 (Token)** | AI가 글을 세는 단위. 단어보다 작은 조각. 문서 기준 **20만 토큰 ≈ 15만 단어**. | p.2, p.22 |
| **컨텍스트 (창) 길이** | AI가 **한 번에 참고할 수 있는 분량**. 길수록 긴 문서를 통째로 다룰 수 있음. | p.2~3, p.22 |
| **프롬프트 (Prompt)** | AI에게 주는 **입력·지시문**. | p.6 |
| **프롬프트 엔지니어링** | 원하는 결과가 나오도록 프롬프트를 다듬는 기술. 목적은 **출력 품질 향상·작업 효율성·확장성**. | p.6 |
| **XML 태그** | `<tag>내용</tag>` 형태의 구획 표시. 프롬프트에서 지시문·데이터·출력형식을 **AI가 헷갈리지 않게 분리**하는 용도. | p.9~10 |
| **시스템 프롬프트** | 대화 전체에 **상시 적용되는 밑바탕 지시**. 매번 반복해 쓸 필요가 없음. | p.10 |
| **사고의 연쇄 (Chain of Thought, CoT)** | 답만 내놓지 말고 **중간 추론 과정을 단계별로 쓰게** 시키는 기법. 정확도가 올라감. | p.10~11 |
| **Few-shot 프롬프팅** | **예시 몇 개를 먼저 보여줘서** 원하는 형식·패턴을 따라 하게 하는 방식. | p.11 |
| **Claude Code** | 터미널에서 쓰는 Anthropic의 **전용 코딩 도구**. `npm install -g @anthropic-ai/claude-code`. | p.11~12 |
| **도구 사용 (tool-use)** | AI가 **외부 API·DB·파일 등을 직접 호출**해 작업하는 기능. API로 제공. | p.2, p.16~19 |
| **input_schema** | 도구가 받을 **입력값의 형식과 필수 항목을 정의한 명세**(JSON Schema). | p.16~17 |
| **tool_use / tool_result** | AI가 "이 도구를 쓰겠다"고 알리는 응답 블록 / 그 실행 결과를 AI에 되돌려주는 블록. | p.18 |
| **프롬프트 체이닝** | 한 프롬프트의 **출력을 다음 프롬프트의 입력으로 이어 붙여** 복잡한 작업을 처리. | p.14~15 |
| **Claude Projects** | 웹에서 **목적별 챗봇을 만드는 기능**. 문서 업로드·지침 설정·팀 공유 가능. | p.19 |
| **멀티모달 / 다중 양식 이해** | 글자뿐 아니라 **이미지·차트·다이어그램도 함께 이해**하는 능력. | p.2, p.23 |
| **확장된 사고 모드** | 어려운 문제에서 **더 오래·체계적으로 추론**하는 모드. | p.2 |
| **Constitutional AI** | Anthropic의 안전성 학습 방식. **지켜야 할 원칙(헌법)을 정해두고** AI가 스스로 답을 다듬게 훈련. | p.3 |
| **RLHF** | *Reinforcement Learning from Human Feedback.* **사람의 선호 평가로 강화학습**시키는 방법. 문서에선 ChatGPT 방식으로 소개. | p.3 |
| **리팩토링** | **동작은 그대로, 코드 구조만 깔끔하게** 고치는 작업. | p.2, p.11 |
| **시간 복잡도 O(n²)** | 데이터가 n개일 때 연산이 **n의 제곱에 비례**해 늘어난다는 뜻. 느림의 지표. | p.13 |
| **의사 코드 (pseudocode)** | 특정 언어 문법이 아닌 **사람이 읽기 쉬운 형태로 쓴 알고리즘 설명**. | p.13 |
| **docstring** | 함수 바로 아래에 쓰는 **공식 설명문**. | p.12 |
| **SDK / API 키** | API를 쉽게 쓰도록 만든 **개발 도구 묶음** / 사용 권한을 증명하는 **비밀 문자열**(노출 금지, 환경 변수 사용 권장). | p.4, p.20 |
| **CI/CD 파이프라인** | 코드 변경 시 **빌드·테스트·배포를 자동 실행**하는 체계 (GitHub Actions, Jenkins 등). | p.25, p.28 |
| **코드 스켈레톤** | 함수·클래스의 **뼈대만 만들어 둔 초안 코드**. | p.25~27 |
| **AJAX** | 페이지 새로고침 없이 **뒤에서 서버와 데이터를 주고받는** 웹 기술. | p.7 |

## 4. 내가 바로 할 수 있는 다음 행동 1개

> ### 🎯 **Claude Code를 설치해서 내 프로젝트 폴더에서 한 번 돌려보기** (소요 10분) `(p.11~12)`

**왜 이것 하나인가**: 이 가이드에서 **읽는 즉시 손으로 확인할 수 있고, 명령어가 그대로 적혀 있는 유일한 항목**입니다. 나머지 기법(체이닝·tool-use·워크플로우 자동화)은 모두 이 도구 위에서 훨씬 쉽게 실습할 수 있습니다.

**실행 절차**

```bash
node -v                                   # 1. NodeJS 18 이상인지 확인
npm install -g @anthropic-ai/claude-code  # 2. 설치        (p.12)
cd <내 프로젝트 폴더>                       # 3. 작업할 곳으로 이동
claude                                    # 4. 실행 → Anthropic 계정 로그인 (p.12)
```

**첫 요청은 p.12의 "명확한 요구사항 제시" 패턴 그대로 써 보세요:**

```
다음 요구사항을 충족하는 함수를 작성해주세요:
  함수명: [이름]
  목적:   [무엇을 하는지]
  입력:   [타입]
  출력:   [타입]
요구사항:
  - [제약 1]
  - 입력값 유효성 검사 포함
  - 주석 및 docstring 포함
```

**마무리**: 결과 코드는 반드시 직접 검토하세요. 문서가 마지막에 못 박은 원칙입니다 — "모든 자동 생성 코드는 인간 개발자의 검토가 필요합니다." `(p.28)`
