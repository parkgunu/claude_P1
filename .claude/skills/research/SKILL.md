# 관심분야 자동 리서치

브라우저 MCP로 여러 사이트를 직접 돌아다니며 정보를 모으고, 출처별로 정리한 마크다운 한 장을 만든다.

## ① 주제·키워드 묻기 (항상 먼저)

추측해서 바로 검색하지 말고 `AskUserQuestion`으로 아래를 한 번에 묻는다. 사용자가 요청에서 이미 밝힌 항목은 다시 묻지 않는다.

- **주제·키워드**: 무엇을 조사할지 (예: "강남구 신사동 맛집", "노이즈캔슬링 헤드폰 비교")
- **범위·조건**: 지역, 기간(최근 3개월 등), 가격대, 제외할 것
- **저장 위치**: 기본값은 사용자가 지금 작업 중인 폴더. 알 수 없으면 물어본다.

## ② 브라우저 MCP로 사이트 3곳 이상 탐색

### 규칙
- 웹 검색·리서치는 **반드시 Playwright MCP**(`mcp__playwright__*`)로 한다. WebSearch/WebFetch로 대체하지 않는다.
- **맛집 주제면 카카오맵을 반드시 포함**하고, 평점 기준 사이트로 쓴다.
- 성격이 다른 출처를 섞는다. 예: 평점·랭킹 사이트 + 사용자 후기(블로그) + 전문/큐레이션 사이트.

| 주제 | 추천 출처 |
|---|---|
| 맛집 | 카카오맵(`map.kakao.com/?q=`), 다이닝코드(`diningcode.com/list.dc?query=`), 네이버 블로그(`search.naver.com/search.naver?ssc=tab.blog.all&query=`), 식신(`siksinhot.com/search?keywords=`) |
| 상품·IT | 제조사 공식 페이지, 다나와, 네이버 블로그/카페 후기, 리뷰 전문 매체 |
| 여행·장소 | 카카오맵, 네이버 블로그, 지자체·관광공사 공식 사이트 |
| 일반 지식·뉴스 | 공식 기관 사이트, 뉴스 검색, 위키 |

### 수집 요령
- 검색어는 URL 쿼리로 넣어 `browser_navigate`로 바로 연다. 입력창 클릭보다 빠르다.
- 목록은 스냅샷을 통째로 읽지 말고 `browser_evaluate`로 필요한 필드만 뽑는다.
  - 카카오맵 목록: `#info\.search\.place\.list > li` → `.link_name`, `.subcategory`, `.score .num`, `.score .numberofscore`, `.review`, `.addr p`, `.moreview`(상세 링크). 다음 페이지는 `#info\.search\.place\.more` 클릭.
  - 다이닝코드 목록: `.PoiBlock`의 `innerText`
  - 사이트 구조가 바뀌어 셀렉터가 안 맞으면 `document.body.innerText`로 텍스트를 먼저 보고 다시 짠다.
- 같은 사이트에서 검색을 여러 번 해야 하면(예: 가게별 블로그 후기) 그 사이트 페이지에 있는 상태에서 `browser_evaluate` 안에서 `fetch` + `DOMParser`로 한 번에 처리한다. 가게마다 페이지를 이동하는 것보다 훨씬 빠르다.
- 블로그 후기는 기간 필터(네이버는 `&nso=so:r,p:3m`)로 최신 글 위주로 보고, 제목에 `내돈내산`·`솔직후기`가 있는 글을 먼저 고른다.

### 데이터 검증
- **동명 지역·동명 가게 걸러내기**: 예) 강남구 신사동 vs 은평구 신사동. 검색 결과에 다른 대상 글이 섞이면 뺀다.
- **표본 수 기준**: 평점은 참여 수가 적으면 믿기 어렵다. 순위에는 기준(예: 50건 이상)을 넘는 것만 넣고, 나머지는 따로 "참고용"으로 분리한다.
- 두 곳 이상의 출처에서 모두 상위권인 항목을 표시한다. 교차 검증된 정보가 가장 믿을 만하다.
- 영업시간·가격처럼 바뀌기 쉬운 정보는 어느 출처의 값인지 적는다.

### 브라우저 오류 대응
`Browser is already in use for ...mcp-chrome-...` 오류가 나면 다른 세션이 브라우저를 쓰고 있는 것이다. 해당 Chrome 프로세스를 찾아 보여 주고, **종료해도 되는지 사용자에게 물어본 뒤** 종료하고 다시 시도한다. 확인 없이 종료하지 않는다.

```powershell
Get-CimInstance Win32_Process -Filter "Name='chrome.exe'" | Where-Object { $_.CommandLine -like '*mcp-chrome-*' } | Select-Object ProcessId, ParentProcessId, CreationDate
```

## ③ 마크다운으로 정리

파일명은 기본 `research.md`. 같은 폴더에 이미 있으면 덮어쓰지 말고 `research-<주제>.md`처럼 주제를 붙인다. 아래 포맷을 그대로 따른다.

```markdown
# <제목: 주제를 한눈에 알 수 있게>

> 수집일: YYYY-MM-DD · 수집 방법: Playwright(브라우저 MCP) 직접 탐색
> 범위: <지역·기간·조건, 제외한 것>

## 출처별 핵심

### 1. <사이트명> — <이 사이트에서 본 것(검색어/경로)>
- 핵심 정보 (수치는 표로 정리. 항목마다 원문 링크)
- ...

### 2. <사이트명> — ...

### 3. <사이트명> — ...

(순위·비교가 필요한 주제면 출처별 섹션 뒤에 "종합" 표를 하나 둔다. 정렬 기준과 표본 기준을 표 위에 적는다.)

## 한 줄 요약

<조사 결과 전체를 한 문장으로. 교차 검증된 결론을 우선한다.>

## 다음 액션

- [ ] 사용자가 바로 할 수 있는 구체적인 행동 (예: "파씨오네 런치 예약 — 발렛 가능")
- [ ] 추가로 조사하면 좋을 것
- [ ] 방문·구매 전 다시 확인할 정보
```

작성 규칙:
- 모든 사실에는 출처 링크를 붙인다. 링크 없는 추측은 쓰지 않는다.
- 수집 범위의 한계(몇 페이지까지 봤는지, 뺀 것과 이유)는 "출처별 핵심" 끝이나 범위 줄에 짧게 적는다.
- 날짜는 오늘 날짜를 절대 날짜로 적는다.

## 마무리 보고

채팅에는 짧게 보고한다:
- 저장한 파일 경로 (클릭 가능한 링크)
- 탐색한 사이트 목록
- 한 줄 요약 + 상위 3~5개 결과
- 알아둘 점 (걸러낸 데이터, 수집 범위의 한계, 브라우저 충돌 등)
