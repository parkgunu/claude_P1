# 냉장고 재료 기반 레시피 추천

재료 하나당 JSON 파일 하나(`week-4/quest/fridge/ingredients/<id>.json`)로 관리되는 냉장고 재고를 읽어,
**유통기한이 급한 재료부터 소진하는** 레시피를 추천하고 `week-4/quest/fridge/recipes/` 에 마크다운으로 저장한다.

## 1. 재고 읽기 (항상 먼저)

추측하지 말고 반드시 스크립트로 폴더를 읽는다.

```bash
node .claude/skills/fridge-recipe/scripts/scan-fridge.mjs week-4/quest/fridge/ingredients
```

- 유통기한 오름차순 마크다운 표 + `먼저 써야 할 재료` / `양념` 요약이 나온다.
- 상태 표기: `❌ 기한초과`(버릴 것) / `🔴 급함`(D-3 이내) / `🟡 곧`(D-7 이내) / `🟢 여유`.
- 구조화된 데이터가 필요하면 `--json`, 날짜를 가정해 보려면 `--today=2026-09-16` 을 붙인다.
- `## 파일 문제` 섹션이 나오면(JSON 깨짐·필수 필드 누락) 레시피를 만들기 전에 그 파일부터 고친다.

## 2. 요리 후보 3개 제시

스캔 결과를 바탕으로 후보 **3개**를 아래 형식으로 한 번에 보여주고 사용자가 고르게 한다.

```
1. 김치두부두루치기 — 🔴 돼지고기 앞다리살(D-2), 🔴 두부(D-3) 소진 · 20분 · 부족한 재료 없음
2. ...
3. ...
```

후보 선정 규칙:
- **1순위는 `❌`/`🔴` 재료를 쓰는 요리.** 급한 재료가 있는데 안 쓰는 후보만 내지 않는다.
- 3개 중 최소 2개는 **부족한 재료 0개**(지금 있는 것만으로 완성)여야 한다.
  나머지 1개는 1~2가지만 사서 만들 수 있는 요리로, 살 것을 명시한다.
- 조리 시간과 종류(국/찌개, 볶음, 밥/면, 반찬)를 서로 겹치지 않게 섞는다.
- 양념(`category: "양념"`)은 재고에 있는 것만 쓴다. 없는 양념이 필요하면 "부족한 재료"에 적는다.
- 사용자가 이미 요리를 지정했으면(`/recipe 김치찌개`) 후보 제시를 건너뛰고 3번으로 간다.
  단, 그 요리에 없는 재료가 필요하면 무엇을 사야 하는지 먼저 알린다.

## 3. 레시피 마크다운 저장

고른 요리를 `week-4/quest/fridge/recipes/<요리이름>.md` 로 저장한다. 파일명에 공백을 넣지 않는다.

```markdown
# <요리 이름>

> 냉장고 재고 기준 <YYYY-MM-DD> · 조리 <N>분 · <N>인분

<왜 지금 이 요리인지 1~2문장. 어떤 임박 재료를 소진하는지 반드시 언급.>

## 냉장고에서 쓰는 재료

| 재료 | 쓰는 양 | 재고 | 유통기한 |
| --- | --- | --- | --- |
| 돼지고기 앞다리살 | 300g | 400g | 2026-09-18 (D-2) |

## 추가로 필요한 것

- 없음  <!-- 또는 사야 할 것 목록. 재고에 있는 양념은 여기 적지 않는다. -->

## 만드는 법

1. <단계마다 불 세기와 시간을 명시. 실패 포인트는 **굵게**.>
...

## 팁

- <대체 재료, 매운맛 조절, 남는 재료 활용>

## 남는 재료

- 돼지고기 앞다리살 100g — 다음 날 볶음밥에
```

작성 규칙:
- 한국어, 담백한 설명체(`~한다`). 팁 섹션만 `~해요` 체를 써도 된다.
- 계량은 `큰술/작은술/g/개`로 통일한다. **"적당히"는 쓰지 않는다.**
- 만드는 법은 6~9단계. 각 단계에 **불 세기와 시간**을 반드시 넣는다.
- `쓰는 양`은 `재고` 를 넘길 수 없다. 넘기면 분량을 줄이거나 "추가로 필요한 것"에 부족분을 적는다.
- 같은 이름의 파일이 이미 있으면 덮어쓰기 전에 사용자에게 확인한다.

## 4. 보고

저장한 파일 경로를 링크로 알려주고, 소진한 임박 재료와 남은 임박 재료를 한 줄로 요약한다.
재고 차감은 **자동으로 하지 않는다.** 사용자가 "다 먹었어", "재고 반영해줘" 라고 하면 그때 5번으로 간다.

## 5. 재고 파일 편집

재료 JSON은 이 스키마를 따른다. 필수 필드는 `name`, `quantity`, `unit`, `expiresOn`.

```json
{
  "id": "egg",
  "name": "달걀",
  "category": "단백질",
  "quantity": 8,
  "unit": "개",
  "storage": "냉장",
  "purchasedOn": "2026-09-08",
  "expiresOn": "2026-10-02",
  "tags": ["주재료", "만능"],
  "note": "특란. 프라이·찜·부침 다 가능"
}
```

- `id` 는 파일명(확장자 제외)과 같게, 영문 소문자 + 하이픈으로 짓는다.
- `category`: `단백질` / `채소` / `채소/절임` / `유제품` / `가공육` / `곡물` / `양념` / `기타`.
- `storage`: `냉장` / `냉동` / `실온`.
- 날짜는 전부 `YYYY-MM-DD`.
- **재료 추가는 파일 추가, 삭제는 파일 삭제.** 한 파일에 여러 재료를 넣지 않는다.
- 다 쓴 재료는 파일을 지우고, 일부만 썼으면 `quantity` 만 줄인다. 삭제 전 사용자에게 확인한다.
